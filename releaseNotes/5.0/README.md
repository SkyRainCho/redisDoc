# Redis 5.0 发布说明

升级紧急程度:

- **LOW**-低: 除非有你想使用的新功能,否则无需升级。 
- **MODERATE**-中等: 计划升级服务器,但不紧急。 
- **HIGH**-高: 存在可能影响部分用户的关键bug。请升级! 
- **CRITICAL**-严重: 存在影响大多数用户的关键bug。请尽快升级! 
- **SECURITY**-安全: 此版本包含安全修复。

## Redis 5.0 介绍
Redis 5.0.0 发布于 2018年10月17日 13:28:26 CEST

升级紧急程度 **CRITICAL**-严重: 对**Stream**、**AOF**和**主从复制**进行了多项修复。

大家好,欢迎使用 Redis 5 的第一个稳定版本! \o/

以下是 Redis 5 的新特性快速回顾:

1. 新的**Stream**数据类型。https://redis.io/topics/streams-intro
2. 新的 Redis 模块 API:定时器、集群和字典 API。
3. **RDB** 现在存储 **LFU** 和 **LRU** 信息。
4. 集群管理器从 **Ruby**(*redis-trib.rb*)移植到 *redis-cli* 中的 C 代码。
查看 `redis-cli --cluster help` 获取更多信息。
5. 新的有序集合命令:**ZPOPMIN/MAX** 及其阻塞变体。
6. 主动内存碎片整理**version 2**。
7. 改进了 **HyperLogLog** 实现。
8. 更好的内存报告功能。
9. 许多带子命令的命令现在有 **HELP** 子命令。
10. 客户端频繁连接和断开时性能更好。
11. 许多 bug 修复和其他随机改进。
12. **Jemalloc** 升级到 5.1 版本。
13. 新增 **CLIENT UNBLOCK** 和 **CLIENT ID** 命令。
14. 添加了 **LOLWUT** 命令。http://antirez.com/news/123
15. 除非为了 API 向后兼容,我们不再使用"slave"一词。
16. 网络层的不同优化。
17. Lua 改进:
    - 更好地将 Lua 脚本传播到从节点/AOF。
    - Lua 脚本现在也可以在从节点上超时并进入 -BUSY 状态。
18. 动态 HZ 以平衡空闲 CPU 使用率和响应性。
19. **Redis** 核心在许多方面进行了重构和改进。

然而,上面的列表并没有真正体现 Redis 5 的所有变化,因为在新版本的开发过程中,核心部分在许多方面都得到了改进。不过,一些被认为安全的改动已经被回溯到 Redis 4 中,因为许多改进很难与修复区分开来。

毫无疑问,最重要的面向用户的改进是多年来引入的新的通用数据类型:流(streams)。

请注意,我们直到几个小时前还在努力改进和修复流,所以虽然我们目前没有发现这个版本中存在严重 bug,但在最初几周内仍需谨慎使用。我们非常感谢 bug 报告,并准备立即着手发布 5.0.1 版本,只要有足够重要的内容来证明新版本的必要性(可能很快就会发布)。

不使用流的用户可能会有更好的生产就绪体验,因为 Redis 5 的许多内部结构与 Redis 4 是共享的,所以在内部工作方式上,这次跨越并不像 3.2 到 4 那样大。

非常感谢 Redis 社区和开发者们使这个版本成为可能,他们贡献了 bug 报告、补丁、新功能,开发客户端,有时甚至花费数天调试问题。也感谢所有采用 Redis 的用户,让它能为全球用户提供服务。

## 从Redis 4.0迁移到Redis 5.0
Redis 4.0 基本上是 5.0 的严格子集,你应该不会遇到任何将应用从 4.0 升级到 5.0 的问题。但是,以下是 5.0 版本引入的一些小的非向后兼容变更:

- redis-cli 现在实现了集群管理工具。我们仍然提供旧的 redis-trib,但新的修复只会在 redis-cli 中实现。
更多信息请参见 redis-cli --cluster help。

- RDB 格式发生了变化。Redis 5.0 仍然能够读取 4.0(以及所有过去版本)的文件,但反之则不行。

- Redis 5.0 中某些日志格式和语句有所不同。

- 现在默认情况下,从节点会忽略 maxmemory 设置,只有当从节点被提升为主节点时才会使用。这意味着在那些希望从节点独立于主节点执行 maxmemory 的设置中(主节点仍会流式传输键驱逐的 DEL 命令),你应该手动激活此功能,并确保理解它在写操作不总是幂等的情况下会破坏一致性。简而言之:新的行为对 99.999% 的用例来说更好,只有在你真正知道自己在做什么的情况下才需要恢复旧行为。

- 脚本现在只通过其效果复制,而不是通过向从节点或 AOF 日志本身发送 EVAL/EVALSHA 来复制。这在一般情况下要好得多,未来我们希望完全移除以旧方式(作为 EVAL)传播脚本的可能性。但是,你仍然可以通过未文档化的 Redis 配置指令 "lua-replicate-commands yes" 或 "DEBUG lua-always-replicate-commands 0" 将其恢复为默认设置。但请注意,Redis 6 可能会完全移除此功能。
